# M0 · 环境与脚手架

- **分支**：`stage/m0-scaffold`
- **目标**：搭好能持续开发的底座，之后每个阶段只需要往里加功能。

## 任务清单

- [x] 开发环境：Node.js 24 LTS、pnpm、微信开发者工具
- [x] uni-app 脚手架：Vue 3 + Vite + TypeScript，只保留微信小程序端，输出到 `dist/mp-weixin`
- [x] 根目录 `project.config.json`：开发者工具直接打开仓库根目录，小程序代码和云函数目录都能识别
- [x] 代码规范：ESLint（含 Vue、TypeScript 规则）+ Prettier
- [x] 类型检查：前端（vue-tsc）、云函数、脚本三套 tsconfig 全部通过
- [x] 单元测试：Vitest，覆盖 `shared/` 与 `cloud/` 的公共逻辑
- [x] 前后端接口约定：`shared/` 中定义云函数的 action 类型与统一返回结构
- [x] 云函数构建：`cloud/` 用 TypeScript 编写，esbuild 按函数打包到 `cloudfunctions/`；先实现 `data` 函数的 `ping`
- [x] 前端调用封装：`services/cloud.ts` 类型安全地调用云函数
- [x] 设计变量：浅色 / 深色两套 CSS 变量，跟随系统切换
- [x] 基础组件：导航栏（大标题随滚动收起）、tab 栏（毛玻璃）、按钮、卡片、骨架屏、图标
- [x] 应用外壳：单页三 tab（练习 / 收藏 / 我的），切换带过渡动画，内容为占位
- [x] 冒烟测试脚本：用开发者工具自动化接口启动小程序、截图
- [x] 发布脚本：用 miniprogram-ci 生成预览二维码、上传体验版、部署云函数
- [x] GitHub Actions：推送和 PR 时自动跑全部检查
- [x] 文档：`docs/REVIEW.md`（审查流程与清单）、`CLAUDE.md`（协作约定），README 按实际结构更新

## 验收标准

1. `pnpm check` 全部通过（格式、代码规范、类型、单元测试、小程序构建、云函数构建）
2. 微信开发者工具打开仓库根目录，模拟器显示三个 tab 的占位页面，浅色 / 深色都正常，tab 切换有过渡
3. 冒烟测试脚本能自动启动小程序并截图
4. GitHub Actions 在 PR 上运行通过
5. 云开发环境开通后，"我的"页面能显示 `ping` 的连通结果（需要你先开通环境，不阻塞 M0 合并）
